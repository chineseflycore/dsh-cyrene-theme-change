DSH「昔涟」人格引擎插件 · 开发任务书（纯文本版）
================================================

一、背景与目标
------------------------------------------------
你是资深 Node.js 与浏览器前端工程师。请实现一个 DeepSeek Harness（简称 DSH）插件，
给 AI agent 加上一个叫「昔涟」的稳定人格，包含长期记忆、关系、情绪与可视化。

DSH 是"一切皆插件"的 AI agent 框架，插件基于 Cordis。

运行环境：
- 语言：Node.js ESM（可以用 JS，也可以加 TS，但必须有测试）
- 客户端：浏览器里跑的 React，用 React.createElement 手写，不引入构建工具
- 持久化：单个 JSON 状态文件
- 分发：一个 npm 包，不做多包拆分


二、技术栈与依赖（照这个来，别自选）
------------------------------------------------
必须用：
1. 插件框架：Cordis（宿主自带），导出 apply(ctx) 与 inject
2. 客户端 UI：React，由宿主注入，用 require("react") 取，不要从 npm 装 react
3. 星图与面板绘制：原生 Canvas 2D，力导向布局自己写（约 400 行），不要引图形库
4. Live2D 渲染：pixi.js@7.4.2 与 pixi-live2d-display 的 cubism4 版，
   两者都从 jsDelivr CDN 加载，版本必须锁死
5. Live2D 运行时：live2dcubismcore.min.js，本地文件随包分发，必须在 NOTICE 里声明
6. 相似度计算：自写 2-gram 加余弦，约 30 行，中文短句够用

Live2D 三件套的加载顺序固定：live2dcubismcore.min.js → pixi.min.js → cubism4.min.js
模型是 Cubism 4 格式：.moc3 + model3.json + 贴图 + motion/*.motion3.json + exp/*.exp3.json

明确不要用：
- three.js 或 Babylon.js（星图手写 Canvas2D 更快更小）
- 任何 embedding 模型（transformers.js、onnxruntime-web、wasm 小模型）
- PyTorch 或 faiss（本机跑不动，也不需要）
- TypeScript 编译器、vite、webpack、esbuild（客户端没有构建步骤）
- Redux、Zustand、MobX（模块级 store 加 useState 足够）
- dayjs、luxon、date-fns（Date 加两位补零就够）
- axios（用原生 fetch）

如果确实要引第三方库，必须同时满足：零依赖、可 CDN 加载、小于 100KB，并在汇报里说明理由。


三、基于什么改（不要另起炉灶）
------------------------------------------------
模型层：DeepSeek 系列（deepseek-v4.1-flash 或 deepseek-flash）。
通过宿主 ctx.get("llm") 取，不要硬编码模型名，按 provider/model 自动解析。

这决定了缓存的经济性：DeepSeek 上下文缓存按前缀命中，
命中价 0.02 元每百万 token，未命中 1.0 元每百万 token，相差 50 倍；
输出 4 元每百万 token（闲时），8 元（峰值）。
峰值时段：周一至周五 09:00-12:00 与 14:00-18:00（Asia/Shanghai）。
所以"系统提示词逐字节稳定"不是洁癖，是直接的钱。

宿主层：DSH 0.2.x 的 cordis 插件体系。复用它的服务，不要自己造：
- ctx.systemPrompt：注册人格、记忆、关系 section（最核心）
- ctx.effect：生命周期（样式表、监听、定时器自动回收）
- ctx.get("llm")：记忆整理那一次辅助调用
- ctx.slots：客户端 UI 槽位（侧边栏按钮、设置页、欢迎语）
- ctx.on：会话事件（抽取用户与助手文本）
- ctx.webServer：/cyrene/* 一组 HTTP 路由
- ctx.theme：深浅色跟随
- ctx.logger：日志

基于的官方插件（直接用，不要重写）：
- @deepseek-ai/dsh-persona：基础人格前缀。我们的 section 要排在它之后，
  用 resolvePersonaOrder 找到它的 order
- @deepseek-ai/dsh-compaction-basic：会话压缩，配 thresholdRatio 0.4、retainRatio 0.2
- @deepseek-ai/dsh-compaction-tool-result-pruner：压缩前剔除超大工具输出，要挂上
- @deepseek-ai/dsh-user-approval：审批缝合点，只在"按会话禁工具"时才需要

上游插件（我们是从它 fork 出来的）：
dsh-cyrene（主题加 Live2D 桌宠）
  派生为 dsh-cyrene-theme（本项目，AGPL-3.0）
      合并 Cyrene-Agent 的认知层（记忆、关系、情绪、星图）

你的任务是在 dsh-cyrene 的壳子上长认知层，不是从空白写一个主题插件。
配色、毛玻璃、桌宠加载、槽位注册这些基础设施已经存在，照用即可。

上游参考项目（只参考思路，禁止拷代码）：
- Playa-0v0/Cyrene-Agent（MIT）：人格与记忆分层、关系数值设计。不要整段复制实现。
- chineseflycore/xilian-agi-like-test（MIT）：记忆池淘汰策略、情绪向量表示。
  不要搬它的 40M 模型。
- Yuuyuko-uu/dsh-xingxi（自定义许可 1.1）：星图的交互与视觉思路。
  注意：一行代码都不能抄。
- Live2D 模型资源：模型作者是依七哒，经 Cyrene-Agent 到 dsh-cyrene 的授权链。
  可直接使用，但必须署名、非商业、保留授权说明。


四、要实现的能力
------------------------------------------------
1. 长期记忆（三层）
   L0 画像：稳定属性（称呼、时区、偏好），每个字段不超过 40 字
   L1 事实：稳定事实（项目路径、技术栈、约定），每条不超过 30 字
   L2 片段：日常经历，可多，靠衰减淘汰

   写入必须确定性：每轮对话结束无条件落一条 L2。
   不要靠"模型觉得重要才写"。实测同一个任务，一个 agent 记了 16 条，另一个记了 0 条。

   提升才用模型：只有 L2 升级到 L1（事实沉淀）这一步调用 LLM 判断。
   写入路径上不调模型，保证又快又稳。

   冲突消解：同一主体的事实更新时，旧值不删除，标上 tags: ["历史"]；
   注入时只取最新值，避免同时注入两条矛盾信息。

   压缩：L2 超过 120 条时，一次取 20 条压成一条摘要。
   摘要标记 isSummary: true，subEntryIds 记来源 id，摘要不超过 600 字。

2. 关系
   四个数值：affinity（亲近）、trust（信任）、familiarity（熟悉），值域 0 到 100；
   外加 turns（轮次）、streakDays（连续天数）、lastSeen（日期）。

   必须会衰减：距上次超过 1 天开始，每天乘 0.985，下限是原值的 55%；
   熟悉度衰减更慢（取 max(factor, 0.8)）。
   只涨不跌的关系没有张力，聊十次和聊一百次必须能感觉到差别。

3. 情绪
   六维：joy、affection、sadness、anxiety、fatigue、anger，值域 0 到 1。
   由当前这条用户消息的关键词与正则驱动，不调模型。
   每轮先整体衰减（约 8 轮掉一半），再叠加本轮增量，单轮单项增量封顶。

   情绪与记忆联动：召回命中"旧记忆"（创建时间超过 3 天）时，
   affection 轻微上升，最多加 0.04。
   没有这一条，就是"记得你，但无动于衷"。

4. 注入（本项目最关键的约束）
   把记忆与关系写进系统提示词，但系统提示词必须逐字节稳定。

   严禁注入每轮都会变的字段：时间戳、轮数、情绪百分比、上一轮状态、"本轮留意"。
   情绪只有跨档时才改文本，且量化成两档（"有点X" 与 "明显的X"）。
   一切排序必须是纯函数，禁用依赖当前时间的排序
   （例如 weight 加 0.2 乘 freshness(now)）。
   摘要条目优先于碎片条目（摘要是多条挤一条的产物，密度最高）。
   注入预算：总 2000 字以内，L2 部分占 70%。

   为什么这条最重要：缓存按前缀命中。系统提示词在 prompt 最前面，
   它变一个字节，后面整段对话历史全部重新计费。
   实测同一批记忆若按时间排序，过一会儿顺序会翻转，
   注入文本跟着抖，缓存白白失效。

5. 人格底稿
   系统提示词里固定一段人格设定，必须包含四块：
   身份：你是谁，和普通助手的区别
   口吻：自称、称呼、语气词、短句习惯、什么时候不用俏皮
   必须守住的边界：不为可爱牺牲准确性、不编造设定、用户说"关掉人格"立刻切中性
   说话样例：3 条 few-shot，固定文本，换模型时用它定调

6. 可视化（次要，可最后做）
   Live2D 桌宠：情绪到表情的映射，面板可开关
   记忆星图：力导向图，节点是记忆，边是语义、标签、层级关系


五、硬性约束（违反即不可接受）
------------------------------------------------
1. 缓存前缀稳定：同一会话连续 10 轮，系统提示词必须逐字节相同
2. 禁止 @ts-nocheck 之类绕过检查来换编译通过
3. 禁止为了跑通而删减功能（例如"先不做音频""先不做网络"）
4. 不许拷贝上游项目代码，Cyrene-Agent 与 dsh-xingxi 只可参考思路
5. 不拆 npm 包，用户明确拒绝 CLI 与 GUI 分装
6. 任何列表、排序、生成文本必须可重现（同输入得到同字节）


六、验收标准
------------------------------------------------
必过一：自动化测试
npm test 全绿，且新增"人格稳定性"套件，至少覆盖：
1. 关系段是纯函数：同输入调用三次，产出字节完全一致
2. 情绪强度 0.49 时不出现情绪行；0.6 出现"有点X"；0.8 出现"明显的X"
3. 关系段不包含"上一轮的状态""可以留意"这类每轮变化的字段
4. 隔 10 天关系下降；隔 60 天有下限（不降到 5 以下）
5. 传入 echo 时 affection 上升

必过二：缓存实测
跑 20 轮对话，统计 cacheReadTokens / (cacheReadTokens + uncachedInputTokens)，
要求大于等于 99%，且 uncachedInputTokens 每轮应只包含"用户新消息"那一小段。

交付物：源码、测试、NOTICE（含第三方代码来源、Live2D 模型原作者署名、
Live2D Cubism Core 声明）、docs/persona-regression.md（说明两层回归怎么跑）。


七、非目标（不要做）
------------------------------------------------
- 不做降本优化：缓存命中率已经 98% 以上，钱应该花在人格上
- 不改 DSH 自带的 preset 选择器：它的选中态是客户端内存态，外部改不动
- 不接本地小模型做记忆整理（已否决）
- 不照搬 40M 参数的情绪模型（本机跑不动，且上游自己都没训出权重）


八、排期建议
------------------------------------------------
第 1 周：记忆三层、关系数值、情绪六维（纯逻辑，可单测）
第 2 周：注入与缓存约束、人格底稿、测试套件
第 3 周：HTTP 路由、客户端面板（设置、记忆列表、关系数值）
第 4 周：Live2D 桌宠、记忆星图

每周结束必须能 npm test 全绿，且不破坏"系统提示词逐字节稳定"这条。


七之二、基于的 theme 包（必须用它的骨架）
------------------------------------------------
本项目就是一个 DSH theme 包，包名 dsh-cyrene-theme。
它的形态是固定的，必须照这个骨架做，不要自己发明打包方式。

目录结构：
  package.json       关键：dsh 字段声明自己是一个 bundle patch
    name 为 dsh-cyrene-theme
    main 为 lib/index.js，这是宿主半入口
    dsh.bundle.patch 指向 ./cordis.patch.yml
    dsh.client 里 platform 为 web，inject 为空数组
  cordis.patch.yml   把自己 insert 进 profile 的插件树
    内容形如：insert 列表里一条 id 为 ui-cyrene-theme，name 为 dsh-cyrene-theme
  lib/index.js       宿主半：HTTP 路由、提示词 section、工具、会话事件
  lib/client.js      客户端半：React 组件、CSS 字符串、槽位注册
  lib/host/          认知层，做成可独立单测的纯函数
    包括 cognitive.js、memory-*.js、relationship.js、worldbook.js、graph.js、live2d-map.js
  assets/            Live2D 模型与贴图
  Background/ meme/  背景图、表情包素材
  test/              手写断言脚本，不引测试框架
  docs/ NOTICE LICENSE

安装方式（用户侧）：
  dsh plugin --profile <profile 名> add <这个包的路径或 npm 名>

为什么必须照这个骨架：
1. DSH 的插件分发单位就是 bundle patch，dsh.bundle.patch 指向 YAML，
   由 loader 把自己 insert 进 profile。自己写一套加载逻辑不会被识别。
2. 一个包同时有宿主半（main）与客户端半（dsh.client），两者一起分发一起启用。
   不要拆成两个包，用户明确拒绝。
3. 客户端半没有构建流程，产物是 loader 能直接执行的 bundle，
   浏览器里只有 require("react") 能解析到。
4. ctx.theme 服务负责深浅色跟随，主题包不要自己维护两套色板切换，
   订阅宿主的主题即可。

认知层必须放在 lib/host/ 下做成纯函数，不要塞进 lib/index.js。
提示词拼装、记忆淘汰、关系衰减这些都要能脱离 DSH 直接单测。

九、客户端工程约束
------------------------------------------------
- 没有构建步骤：客户端产物是宿主 loader 能直接执行的 bundle
- 样式用 style 标签注入 head，带 data-plugin-css 属性等于包名，插件卸载时移除
- 所有 addEventListener、setTimeout、requestAnimationFrame、ResizeObserver
  必须在卸载时清理，否则热重载会泄漏
- 不碰宿主的 DOM 结构，只往自己的槽位里挂东西；
  样式一律用 body[data-自己包名] 收敛作用域


十、附：已知的坑（省你半天）
------------------------------------------------
1. 客户端 bundle 里只有 require("react") 能解析，其它第三方包会失败
2. 槽位注册失败会拖垮整个客户端入口（GUI 起不来），
   所以每处 slot 注册都要单独 try/catch，失败只记 warn
3. 启动参数不接受 --host 0.0.0.0（会被拒），要绑具体 IP 或回环地址
4. 状态写入必须带版本号（rev），旧版本写入会被拒并回传最新快照，
   客户端要能重读再写
5. 想在系统提示词里注入内容，用 prompt.section({name, order, text})，
   order 要排在 persona 之后
6. 客户端的样式如果和宿主已有类名撞了（例如 .cyre-mode 被设置页占用），
   会静默覆盖宿主的控件，务必用自己独有的前缀


完成标准再强调一次：npm test 全绿，且系统提示词在连续 10 轮里逐字节不变。
